--------------------------------------------------------------------------------
ARCHITECTURE-LEVEL CONCERNS
--------------------------------------------------------------------------------

A1. No ownership model for SSL_session.
    Application, IOCP completion and deletion threads all touch the same
    struct with implicit "hold psession->lock sometimes" discipline. Used in
    session_send_data, ignored in session_close, released mid-deletion in
    session_on_completed_packets. Root cause of ~half the concrete bugs in
    the server section.
    Direction: refcounted SSL_session, free only when refcount==0.

A2. No backpressure / flow control.
    session_send_data busy-loops with Sleep(0) and a 5-second wall-clock
    timeout instead of queueing on WSASend completion. Under congestion this
    starves IOCP workers and deletes clients incorrectly.
    Direction: per-session send queue serviced by WSASend completions.

A3. No bounds anywhere.
    No max concurrent connections, no max message size, no handshake/idle
    timeout, ~6.9 MB inline buffers per session. A single misbehaving peer
    OOMs the server.

A4. Coarse-grained global state.
    m_ClientContext / m_ClientList_forDeal / m_ClientList_forOrder /
    m_SymbolHighLowTimeWiseArray / m_SymbolSourceArray are all CMaps guarded
    by one CMutex. Hot paths iterate without locking.

A5. Sleep-based polling everywhere.
    Sleep(0), Sleep(100), Sleep(5000), while(m_recvThreadSrynk==1) {}.
    Direction: Events, condition variables, completion-based notifications.

A6. WebSocket protocol implementation is partial.
    No control-frame handling, no ping/pong, no close-frame handling, no MASK
    validation, no max frame size, no fragmentation invariants, no
    permessage-deflate.
    Direction: implement RFC 6455 fully or adopt libwebsockets / Beast.

A7. Three mostly-duplicated socket layers.
    ClientSocket.cpp and UniFeederSocket.cpp are ~85% identical; SocketServer.cpp
    is dead. Bugs need fixing in three places.
    Direction: consolidate into one abstraction; delete SocketServer.cpp.

A8. Build artifacts in the repo.
    ~18,555 generated files tracked. .gitignore is a generic Node template.
    Direction: install the standard VS .gitignore; git rm --cached the rest.

A9. CStaticClass god-singleton.
    Hundreds of static members carrying virtually all program state, accessed
    from ~10 threads with inconsistent locking and read-modify-write races.
    Direction: split into purpose-specific services owned by a coordinator.

ID: S1
SEVERITY: CRITICAL
TITLE: DataBuffer::Clear() allocates 1 byte but advertises 10 MB
FILE: OrikaServer/server/DataBuffer.cpp:55
CODE:
  char* new_char=new char(10000000);
  pBuffer=new_char;
  this->uMaxSize = 10000000;
  uSize=0;
WHY:
  new char(N) (parentheses) allocates a single char initialised to (N & 0xFF),
  not an array. Append/Pop/memmove then write up to 10 MB into a 1-byte
  allocation, and ~DataBuffer runs delete[] on a non-array pointer. Double UB:
  heap corruption plus invalid deallocation. Re-confirms prior audit C1.
FIX:
  new char[10000000] - or remove the magic constant and reuse Allocate(uMaxSize).
IMPACT:
  Eliminates an immediate heap-corruption / UB trigger on every Clear() call
  (called per-frame in the deframer). Likely root cause of "random" crashes
  anywhere downstream.

ID: S2
SEVERITY: CRITICAL
TITLE: Disconnection branch keyed on status == 8 (CONNECTED), not CLOSED
FILE: OrikaServer/server/openssl_iocp.cpp:691-696
CODE:
  bool close_session = (CLOSED == p->psession->status);   // computed, never used
  session_unlock(p->psession);
  if (p->psession->status == 8) { ... session_delete(p->psession); ... }
WHY:
  CONNECTED = 0x8, CLOSED = 0x80 (enum in openssl_iocp.h:25-36). The
  "delete the session" cleanup runs on the first IO completion of any healthy
  connected session, freeing it while other overlapped operations and
  m_ClientContext entries are still live.
FIX:
  Replace status == 8 with close_session (or psession->status & CLOSED), and
  read it under the lock.
IMPACT:
  Single highest-impact fix. Almost certainly removes a large class of session
  use-after-free crashes and "ghost client" bugs.

ID: S3
SEVERITY: CRITICAL
TITLE: Session lock released before reading/deleting session - use-after-free race
FILE: OrikaServer/server/openssl_iocp.cpp:694-771
CODE:
  session_unlock(p->psession);
  ...
  if (p->psession->status == 8) {
      session_lock(p->psession);
      session_close(p->psession);
      session_unlock(p->psession);
      ...
      session_delete(p->psession);
  }
WHY:
  After unlocking on line 694, code dereferences p->psession and ultimately
  calls session_delete, which free()s the struct that contains the OVERLAPPED
  structures. Another IOCP worker can simultaneously complete WSARecv/WSASend
  on that same session and dereference freed memory.
FIX:
  Introduce a refcount or dedicated "pending-delete" status; drain outstanding
  async ops before session_delete. Never free SSL_session while OPERATING is
  set or while another thread holds a pointer.
IMPACT:
  Eliminates a class of heap-corruption crashes in IOCP workers under
  concurrency.

ID: S4
SEVERITY: CRITICAL
TITLE: WebSocket deframer buffer overflow - peer-controlled length unchecked
FILE: OrikaServer/server/FrameAndDeframeMessage.cpp:75, 85, 96, 102, 120
CODE:
  payloadSize = ntohl(*(u_long*)(m_databuffer.GetBuffer() + 6));   // 8-byte length path
  memcpy(psession->frame_buffer,
         m_databuffer.GetBuffer() + masksOffset + extra_headerSize,
         m_databuffer.GetDataSize() - masksOffset - extra_headerSize);
  memcpy(psession->LastFrame + psession->LastFrame_size, payload_t,
         psession->frame_buffer_size);
WHY:
  (1) payloadSize is signed int - peer-supplied 64-bit length above 2^31
  becomes negative then huge unsigned. (2) The 127 (8-byte length) path reads
  ntohl of 4 bytes from offset 6 - top 4 bytes silently dropped, non-spec for
  payloads >= 4 GB and miscomputes many smaller ones. (3) frame_buffer is
  BUFFER_SIZE (900000) bytes but no bound check vs
  m_databuffer.GetDataSize() - masksOffset - extra_headerSize. (4) LastFrame_size
  + frame_buffer_size not bounded vs BUFFER_SIZE; fragmented messages can write
  past LastFrame. (5) Continuation path (line 96) and chunked-copy path
  (line 102) likewise lack bound checks. A single malicious frame
  crashes / corrupts heap.
FIX:
  - Make payloadSize uint64_t; for basicSize==127 read all 8 bytes via
    _byteswap_uint64.
  - Define and enforce a server-side max payload (e.g. 1 MB). Reject larger.
  - Validate dst_size + chunk <= dst_capacity before every memcpy.
  - Require MASK bit on client->server; close on violation.
IMPACT:
  Closes the largest remote attack surface in the codebase. Removes a
  single-frame crash/RCE vector. Brings deframer toward RFC 6455 compliance.

ID: S5
SEVERITY: CRITICAL
TITLE: Per-frame heap leak of payload_t in deframer
FILE: OrikaServer/server/FrameAndDeframeMessage.cpp:112-120
CODE:
  char* payload_t = new char[psession->frame_buffer_size + 1];
  for (...) payload_t[i] = (psession->frame_buffer[i] ^ psession->masks[i % 4]);
  payload_t[psession->frame_buffer_size] = '\0';
  memcpy(psession->LastFrame + psession->LastFrame_size, payload_t, psession->frame_buffer_size);
  // no delete[] payload_t along any path
WHY:
  Every received WebSocket frame leaks frame_buffer_size + 1 bytes; unbounded
  steady-state growth under load.
FIX:
  delete[] payload_t before every return, or XOR-unmask directly into
  LastFrame + LastFrame_size and drop the temporary.
IMPACT:
  Stops continuous memory growth that eventually OOM-crashes the server.

ID: S6
SEVERITY: CRITICAL
TITLE: Hardcoded TLS private key in source + SSL_VERIFY_NONE
FILE: OrikaServer/server/cert.cpp:46-71, 114-141; openssl_iocp.cpp:168
CODE:
  // cert.cpp embeds a full "-----BEGIN PRIVATE KEY-----...-----END PRIVATE KEY-----"
  SSL_CTX_set_verify(ssl_ctx, SSL_VERIFY_NONE, nullptr);
WHY:
  Anyone with access to source or a stripped binary recovers the server
  private key. Combined with VERIFY_NONE, TLS becomes trivially MITM-able once
  the key leaks. The binary actually loads key.pem from disk
  (openssl_iocp.cpp:179-191) so the embedded blob is dead weight that just
  leaks the secret.
FIX:
  Rotate immediately, delete ca_cert_key_pem and server_cert_key_pem from
  cert.cpp. Decide whether to enable client cert auth with SSL_VERIFY_PEER +
  a CA bundle.
IMPACT:
  Restores TLS as an actual confidentiality and authenticity boundary.
  Removes a credential-exposure compliance failure.

ID: S9
SEVERITY: CRITICAL
TITLE: WebsocketHandshakeMessage::Parse() underflows request[-1] on empty input
FILE: OrikaServer/server/WebsocketHandshakeMessage.cpp:43, 62
CODE:
  std::getline(s, request);
  if (request[request.size() - 1] == '\r') { ... }
